# СимфИнвестСтрой — сайт компании по ремонту квартир

Одностраничный сайт-визитка компании в Симферополе: услуги, цены, галерея,
отзывы-вопросы и форма заявки. Заявки с формы уходят на e-mail и дублируются
в журнал на сервере. Telegram не используется.

## Возможности

- адаптивная главная: слайдер, цены, блок «О нас», галерея, миссия, FAQ;
- форма заявки с маской телефона, валидацией и согласием на обработку
  персональных данных;
- страница политики обработки персональных данных (`/privacy`);
- антиспам: honeypot, минимальное время заполнения, лимит по IP, проверка Origin;
- SEO: meta-теги, Open Graph, JSON-LD, `sitemap.xml`, `robots.txt`;
- SPA-маршрутизация через `.htaccess` (прямые ссылки и перезагрузка страниц).

## Стек

- React 19, TypeScript, Vite 8
- Tailwind CSS 4 (`@tailwindcss/vite`, тема в `src/index.css`)
- react-hook-form + zod
- Swiper, yet-another-react-lightbox
- Backend: PHP 8 без фреймворков — `public/send.php`

## Требования

- Node.js 20+ и npm;
- PHP 8.0+ с `mbstring`, `curl` и включённой `mail()` (на хостинге reg.ru есть);
- Apache с `mod_rewrite` (для SPA-маршрутизации) либо настройка fallback на
  `index.html` на стороне сервера.

## Сборка

```powershell
npm run build
```

Команда запускает `tsc -b` и `vite build`, результат — в `dist/`. Папка `dist`
в git не хранится: её содержимое загружается на хостинг.

## Деплой на reg.ru

1. `npm run build`.
2. Загрузить **содержимое** `dist/` (не саму папку) в корень сайта:
   `/var/www/u3701944/data/www/simf-invest-stroy.ru/`.
3. `.htaccess` — скрытый файл. В файловом менеджере включить показ скрытых
   файлов или загрузить по FTP. Без него `/privacy` отдаёт 404.
4. `config.php` не входит в `dist` и лежит на уровень выше корня сайта:
   `/var/www/u3701944/data/www/config.php`.
5. Проверить после загрузки:
   - `https://simf-invest-stroy.ru/privacy` → 200;
   - `https://simf-invest-stroy.ru/send.php` (GET) → 405 и JSON;
   - форма на сайте отправляется, в `requests.log` появляется строка.

Загрузка новой сборки не удаляет старые файлы с сервера. Если нужно освободить
место, неиспользуемые файлы удаляются вручную в файловом менеджере.

## Конфигурация

`config.php` лежит вне корня сайта, в git не попадает. Структура:

```php
<?php
return [
    'email' => [
        'to'   => 'alim.simf@mail.ru',             // куда приходят заявки
        'from' => 'no-reply@simf-invest-stroy.ru', // отправитель на домене
        'smtp' => [
            'enabled' => false,
            'host'    => 'mail.hosting.reg.ru',
            'port'    => 465,
            'secure'  => 'ssl',
            'user'    => 'no-reply@simf-invest-stroy.ru',
            'pass'    => '',
        ],
    ],
    'max' => [
        'token'      => '',
        'chat_id'    => '',
        'user_id'    => '',
        'verify_ssl' => true,
        'ca_info'    => '',
    ],
    'allowed_origins' => [
        'simf-invest-stroy.ru',
        'www.simf-invest-stroy.ru',
        'localhost',
        '127.0.0.1',
    ],
    'log_file' => __DIR__ . '/requests.log',
];
```

- `email.to` — получатель заявок; `email.from` — адрес отправителя на домене.
- `email.smtp` — включается (`enabled => true`), если `mail()` даёт сбои или
  письма попадают в спам. Пароль — от ящика на домене.
- `max` — опциональный канал. По умолчанию выключен: пустые `token` и
  `chat_id`. Код отправки готов, включение выполняется только конфигом.
- `allowed_origins` — домены, с которых разрешена отправка формы.
- `log_file` — путь к журналу заявок.

## Приём заявок

Форма отправляет POST на `/send.php` с JSON:

```json
{
  "name": "Иван",
  "phone": "+7 (978) 123-45-67",
  "city": "Симферополь",
  "kvm": "45",
  "page": "/",
  "ts": 1762288000000,
  "website": ""
}
```

`ts` — время открытия формы в миллисекундах, `website` — honeypot (должно быть
пустым). Сервер валидирует поля повторно и не доверяет клиенту.

Поддерживается и старый формат `{"text": "..."}` — для совместимости с ранее
закэшированными версиями фронтенда. Блок «Временная поддержка старого формата»
в `send.php` можно удалить, когда он перестанет быть нужен.

Ответы:

| Код | Значение |
| --- | --- |
| 200 | `{"ok":true}` — заявка принята хотя бы одним каналом |
| 400 | неверный запрос или слишком быстрое заполнение |
| 403 | домен источника не в `allowed_origins` |
| 405 | GET вместо POST (нормально для проверки) |
| 422 | не прошла валидация полей, в `fields` — причины |
| 429 | больше 5 заявок в минуту с одного IP |
| 500 | не найден или не читается `config.php` |
| 502 | не сработал ни e-mail, ни MAX |

Каждая заявка пишется в журнал независимо от результата отправки.

## Журнал заявок

`requests.log` лежит рядом с `config.php`, по строке на заявку, поля через
табуляцию:

```
дата  IP  имя  телефон  город  площадь  страница  email-статус  max-статус
```

Пример:

```
2026-11-04T22:50:00+03:00  195.26.82.203  Иван  +7 (978) 123-45-67  Симферополь  45  /  email: ok  max: не настроен
```

Из браузера журнал недоступен: он вне корня сайта. Журнал — резервная копия
заявок на случай сбоя почты.

## Почта и DNS

- Домен `simf-invest-stroy.ru`, MX → `mx1/mx2.hosting.reg.ru`, SPF настроен.
- DNS-зоной управляет Cloudflare (`jimmy.ns.cloudflare.com`,
  `pat.ns.cloudflare.com`).
- Записи MX, SPF и DMARC менять не нужно — на них держится почта домена.
- Если письма попадают в спам: включить SMTP в конфиге или добавить
  `no-reply@simf-invest-stroy.ru` в контакты получателя.

## MAX (опционально)

Канал реализован, но по умолчанию выключен. Чтобы включить:

1. Создать бизнес-профиль и бота на `business.max.ru`, скопировать токен.
2. Написать боту сообщение, затем получить `chat_id` из
   `GET https://platform-api2.max.ru/updates` с заголовком
   `Authorization: <token>`.
3. Вписать `token` и `chat_id` в `config.php` — пересборка не требуется.

## SEO и маршрутизация

- Канонический домен — `https://simf-invest-stroy.ru`, задаётся в
  `src/data/site.ts` и в `index.html`.
- `<title>`, `description`, Open Graph и JSON-LD находятся в `index.html`;
  для отдельных страниц — компонент `Seo`.
- `sitemap.xml` и `robots.txt` лежат в `public/`.
- `/privacy` закрыта от индексации (`noindex`).
- `.htaccess` отдаёт `index.html` для всех несуществующих путей — это нужно
  для работы `/privacy` и других клиентских маршрутов.

## Контент и обслуживание

- Контакты — `src/data/contacts.ts`; домен и название — `src/data/site.ts`.
- Цены, галерея, слайды, FAQ — `src/data/*.ts`.
- Текст политики — `src/pages/PrivacyPage.tsx`.
- Изображения — `public/images`, подключаются по абсолютным путям `/images/...`.
- После любых изменений: `npm run build` и повторный деплой `dist/`.
- `config.php` и `requests.log` не коммитить; они исключены через `.gitignore`.
- Бэкап перед обновлением: скачать `public_html` и `config.php`.
- Откат файла: `git checkout -- <путь>`.

## Типовые проблемы

| Симптом | Причина | Решение |
| --- | --- | --- |
| `{"error":"Сервис временно недоступен"}` | `config.php` не найден | положить на уровень выше корня сайта |
| `{"error":"Метод не поддерживается"}` | GET вместо POST | нормально для проверки |
| `403 Запрос отклонён` | домен не в `allowed_origins` | добавить домен в конфиг |
| `429` | больше 5 заявок в минуту с IP | подождать минуту |
| `502` | не ушло ни письмо, ни MAX | смотреть `requests.log` |
| `/privacy` → 404 | нет `.htaccess` или Apache его не читает | загрузить `.htaccess` |
| 500 после загрузки `.htaccess` | хостинг запрещает директивы | оставить только блок `mod_rewrite` |
| `Parse error` в `send.php` | файл обрезан при копировании | загружать целиком, проверять размер |
